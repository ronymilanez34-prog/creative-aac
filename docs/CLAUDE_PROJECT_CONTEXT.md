## מי אני ומה הפרויקט
אני רוני (rony.milanez34@gmail.com), היוצר של **Creative AAC — תקשורת חלופית יוצרת**.
Repo: `github.com/ronymilanez34-prog/creative-aac`. ענף ראשי: `main`.
כלי תקשורת חלופית (AAC, תת"ח) **יוצר** לאנשים על הרצף האוטיסטי: לא לוח "בקשות"
קבוע, אלא סביבה שבה המשתמש **יוצר** יחד עם AI (סיפורים היום; בהמשך משחקים ועוד)
ומתקשר **דרך היצירה**. המוטו: "אני נותן להם את המכחול — הם הציירים."
העיקרון האתי: "בדיוק כמוני" — שמחת היצירה מול AI מגיעה לכל אוטיסט באותה עוצמה.
מסגרת של עושר, לא של חוסר: לא מתקנים ליקוי, משחררים ביטוי שכבר קיים.

## הבעיה
אי-ההבנה בין אוטיסטים לנוירוטיפיקלים היא דו-כיוונית (Double Empathy Problem, מילטון).
כלי AAC קיימים: רשימת סמלים סגורה, לא לומדים את האדם, אין מקום ליצירה,
והמשפחה והמלווים נשארים מחוץ לשיחה.

## הפתרון — שלושה רכיבים
1. **פרופיל אישי (הלב):** זיכרון מצטבר של האידיולקט של האדם — איך *הוא* מחבר
   סמלים למשמעות (למשל 🔴+🏠 = "רוצה הביתה עכשיו"), נושאים חוזרים, טריגרים, העדפות.
   שקוף, שייך למשתמש, ניתן למחיקה. לא fine-tuning.
2. **מנוע פירוש:** קלט דליל + פרופיל → כוונה סבירה → **מאשר מול המשתמש**. לעולם לא מכריע בשקט.
3. **תרגום דו-כיווני:** החוצה — הקול האותנטי + ניסוח ברור לנוירוטיפיקל; פנימה — פישוט קלט של אחרים.

ארבע שכבות למידה: 0 בסיס (Claude, עם הטיה נוירוטיפיקלית) → 1 מאגר ידע תת"ח
ב-RAG (רופף בכוונה) → 2 פרופיל אישי (גובר על הכללי) → 3 כיול אנושי עם קלינאי תקשורת.
Cold start נפתר על ידי קלינאי תקשורת + מנתח התנהגות. אין "שפה אחת של תת"ח".

## עקרונות עיצוב (לא לשבור)
- צפוי ורגוע: צעדים ליניאריים, בלי הפתעות, בלי הבהובים.
- בחירה על פני הקלדה; טקסט חופשי אופציונלי. "שיחה חופשית נתמכת": ה-AI תמיד
  מציע 3-4 המשכים ללחיצה. אף אחד לא נתקע מול שדה ריק.
- שליטה מלאה למשתמש: כלום לא מתקדם לבד, תמיד יש "חזרה".
- פחות טקסט, יותר תמונה. אימוג'י גדולים. הקראה קולית בעברית בכל מקום.
- צבעים רכים, ניגודיות טובה. RTL.
- שני מצבים: מצב משתמש (פשוט, שלו) ומצב מלווה/קלינאי (עורך פרופיל, רואה ניחושים, מתקן).
- מדד הצלחה: כמה ביטוי, שמחה וסוכנות — לא "כמה מדויק תרגמנו".

## טכנולוגיה ומצב נוכחי
- **Flutter** (Dart), `flutter_tts` להקראה. תיקיות הפלטפורמה לא ב-repo (`flutter create .`).
- Backend: **Firebase Cloud Function** (`functions/`) שמדבר עם Claude; המפתח
  (`ANTHROPIC_API_KEY`, `APP_KEY`) ב-Secret Manager, לעולם לא באפליקציה.
  חיבור דרך `--dart-define=COMPANION_ENDPOINT` ו-`COMPANION_APP_KEY`. בלעדיהם: מצב אופליין מלא.
- מבנה: `lib/screens` (home, companion, partner, build_story, story_view, my_stories),
  `lib/services` (companion_service, claude_companion_service, profile_store,
  interaction_log, story_generator, speech, story_store), `lib/data/choices.dart`.
- פרומפט המערכת: `docs/prompts/companion_system_prompt.md`.
- **סטטוס (HANDOVER 4.9.2026):** MVP לפיילוט בנוי וירוק ב-CI. קיים: לולאת יצירה
  מחוברת ל-Claude, פרופיל + מצב מלווה, לוג מדידה על המכשיר, פס חירום, מצב אנרגיה
  נמוכה, ייבוא לוחות .obz/.obf, שמירת יצירות, CI שבונה APK וווב. ממתין: הדלקת הענן
  לפי SETUP.md ופיילוט בכפר. מפת דרכים: תרגום דו-כיווני, RAG, TTS ענן.
- פיתוח נעשה לרוב מהטלפון דרך Claude Code (ללא מחשב פיתוח). GitHub בונה הכל.
